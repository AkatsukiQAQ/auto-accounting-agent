### 2. Multi-receipt import (extends Phase 1)

`POST /api/import/photo` originally returned `{previewTransaction}` (single).
The legacy pipeline / current pipeline both extract **all receipts in one
image** (e.g. PayPay screenshot with 5 transactions), but the design doc
told us to drop everything but the first and log a warning. That assumption
broke real usage — most user uploads are multi-receipt screenshots.

Backend changes:
- `backend/api/schemas/import_.py`: `previewTransaction` →
  `preview_transactions: list[TransactionCreate]`; `confidence` →
  `confidences: list[float]` (parallel to drafts).
- `backend/api/routes/imports.py`: drop the "keep first" branch; iterate
  `parsed_ocr_results` and emit one preview per receipt. Empty-OCR fallback
  still returns one placeholder.
- `backend/tests/api/test_imports.py`: existing tests updated to read the
  new field; **new test** `test_import_photo_multi_receipt_returns_all`
  verifies 3 receipts → 3 previews + parallel confidences.
- 168/168 backend tests green.

Frontend changes:
- `lib/types.ts`: `ImportPhotoResponse` field rename.
- Step 2 of Import: was a single edit form; became an N-card carousel.

### 3. Quick-import + carousel (UX redesign)

Original Phase 1 sent every draft through a manual confirmation card.
For a 5-receipt screenshot that's tedious. User asked for two changes:

1. **Settings toggle "Quick import"** + a confidence threshold slider
   (0.50–0.95, default 0.80, disabled when toggle off). Stored under
   `user_settings.import.{quickImport, confidenceThreshold}` — no backend
   schema change since `user_settings.data` is JSON.
2. **Per-draft carousel UI** showing one card at a time with `Previous /
   Skip / Save next / Save all remaining` buttons. CSS keyframe transitions
   (slide-in-from-right when advancing, slide-in-from-left when going back).

Logic flow when user uploads a photo:
- Pipeline returns N preview drafts.
- If `quickImport === true`: drafts where `confidence ≥ threshold` AND
  `merchant !== "Unknown"` AND `amountCents !== 0` are POSTed automatically.
  The rest stay in the carousel for confirmation.
- If `quickImport === false`: all drafts go through the carousel.

The "deck-of-cards floating modal" alternative was discussed and **rejected**
for Phase 1 — adds animation latency without speed benefit; receipt
confirmation is a "clear the queue fast" task, not a leisurely browse.

### 4. Job queue + tab-switch bug fix

Reported bug: clicking the Manual tab during a 60-second pipeline run
killed the in-flight state because `PhotoTab` unmounted on tab switch.
Switching back showed "Upload" instead of "Processing" while the request
silently continued and its result was discarded.

Fix: lifted all photo state from `PhotoTab` into `ImportPage`. Inlined the
photo flow rather than leaving it in a sub-component.

While there, built the prototype's "Processing queue" (visible in
`design/design-references/src/screens.jsx::ImportScreen` line 143). Job
data model lives in `frontend/src/lib/importJob.ts`. `JobQueueRow`
component renders the strip in the Import page.

States used:
- `processing` — pipeline running (shows elapsed-second counter)
- `reviewing` — drafts ready, carousel active
- `done` — fully handled, fades from queue after 60 seconds
- `error` — kept out of the queue; shown as top-level alert in the
  upload zone

Naming alignment with the prototype's `working / review / done` is
**deferred to Phase 2** by user decision (see Sticky decisions §B).

### 6. Typography (locked — see Sticky decisions §C)

Three font-stack iterations driven by user feedback:
- Kalam (prototype default) — felt too stylized at body sizes.
- Patrick Hand — too uniform, "rounded printed font".
- Caveat — too cursive/slanted ("花").
- Indie Flower — clean upright, but light at title sizes.
- **Settled mix**: Kalam-700 for `.hand` (titles, KPI numbers, brand);
  Indie Flower-400 for `.hand-body` (Mita's tips header, future
  conversational copy). See `frontend/src/index.css`.

### §B. Phase 2 import flow alignment (deferred work)

Phase 1 currently sends every draft from `/api/import/photo` to the
carousel. Phase 2 will reshape `/api/import/photo` per

  `previewTransactions[]` (Phase 1 path).
- **Low-confidence**: backend writes to a new `review_queue` table,

  can surface "N items went to /review".

Required frontend changes when Phase 2 lands:

   `reviewQueueItems` (one upload can yield mixed confidences).
2. `ImportPage`: when `reviewQueueItems.length > 0`, add a queue row
   variant linking to `/review`. Carousel still drives only the
   `previewTransactions` subset.
3. **Rename `JobStatus`** strings: `'processing' → 'working'`,
   `'reviewing' → 'review'`. Touchpoints: `lib/importJob.ts`,
   `components/import/JobQueueRow.tsx` (STATUS_COLOR map + summary
   text), `pages/ImportPage.tsx` (status assignments). Deferred until
   Phase 2 alignment so we rename everything once.
4. Build `frontend/src/pages/ReviewPage.tsx` for `/review`. Reuses
   `DraftCard` + Save/Skip/Previous cluster.
5. Settings: re-evaluate the `confidenceThreshold` slider once the

   the slider may become irrelevant or migrate to a different role.

Errors are intentionally **not** a JobStatus — they show as top-level

### §C. Typography rules

`.hand` is **locked to Kalam-700 across all locales**. Used for:
SideNav brand, Dashboard hero greeting, KPI hero numbers, page-level
handwritten emphasis.

`.hand-body` is locale-swappable:
- English (current): Indie Flower 400.
- Phase 3 i18n work: under `[lang="zh"]` swap to Ma Shan Zheng;
  under `[lang="ja"]` swap to Klee One. Override **only**
  `--font-hand-body`. Don't touch `--font-hand`.

Don't introduce a third hand font without revisiting this contract.

The CSS lives in `frontend/src/index.css` (`@theme` declarations + the
`.hand` / `.hand-body` / `.serif` / `.num` utility classes).

### §D. API key source of truth

OpenAI key lives **only** in `user_settings.apiKeys.openai` (SQLite).
The running server does not read `OPENAI_API_KEY` from env. The dev
helper `make seed-api-key` reads `.env` and pushes the key into the DB
so a local `make db-reset` cycle isn't followed by a Settings-page
visit. See `backend/scripts/seed_api_key.py`.

### §E. Architecture invariants

- Backend layer order is strict: `core/` (pure) ← `services/` ←
  `api/`. `core/` only depends on `pydantic` + `PyYAML`; verifiable via
  `uv sync --extra core-only` (the audit runs the core-only deps and
  expects core tests to still pass).
- Backend HTTP responses: success → `{"data": T}` (single-key
  envelope, frontend's `fetchJson` auto-unwraps). List endpoints like
  `/api/transactions` return `{data, nextCursor}` siblings — frontend
  handles that explicitly (see `lib/api.ts` for the unwrap rule).
  Errors → `{"error": {"code", "message", "meta"}}`.
- Pipeline LLM calls go through `OpenAIPipelineLLM` which uses
  `client.chat.completions.parse` (not `responses.parse` — that was a
  plan-doc typo caught during M2 exploration). Temperature is omitted
  by default because GPT-5 family rejects custom values.
