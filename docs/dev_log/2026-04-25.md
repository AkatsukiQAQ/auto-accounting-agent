### Known limitations exposed by the smoke

- **京急ストア → shopping** instead of food: the legacy YAML's `Supermarket` category had only one specific keyword (`もとまちユニオン`). Fix path: edit `food.keywords` via `PATCH /api/categories/food`. Phase 3 plans a corrections-learning loop.
- **Multi-receipt screenshots → first only**: route logs a warning, drops the rest. Frontend assumes one-per-upload (`PHASE_1.md`). Phase 2 may revisit.
- **Latency (~1 minute) is gpt-5-nano's price**, not our code's. Switching `LLM_MODEL=gpt-4o-mini` would likely halve it. Streaming is a Phase 2/3 ergonomic.

## Decisions locked in this phase (recap)

1. LLM model default: `gpt-5-nano`
2. Phase-1 category seeder: `db/seeders/categories.py` (color values stay out of `core/`)
3. No legacy↔new diff; smoke test on real receipts is the parity story
4. Service param naming: `start/end/categories/search` internally, `from/to/category/q` over HTTP
5. `update_*` keeps `**updates` — pairs naturally with Pydantic `model_dump(exclude_unset=True)`
6. **OpenAI key only in SQLite (`user_settings.apiKeys.openai`)**, never read from env. `make seed-api-key` exists for dev convenience.
7. Image storage default `./storage/images` (gitignored)
